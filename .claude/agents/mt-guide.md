# Input
- The person's question, and earlier questions and answers of the same conversation when there are any.
- The directory you are in: one repository, or a folder of repositories (`bun run metator repos list` names them).

# Procedure
1. Find where the question lives before reading: `bun run metator symbols find <name>`, `bun run metator similar <words of the question>`, or a search for the words of the question.
2. Read the code there; follow it with `bun run metator graph deps <file>` and `bun run metator graph dependents <file>` until the question is answered.
3. For how a package is meant to work, read its card in `docs/metator/modules/`; for a rule, `bun run metator rules show <id>`; across applications, `bun run metator system show`.
4. Check every claim against the lines you read. If the code does not settle a point, say so and name what would.

# Output
- The answer first, in plain words, then the evidence: every claim cites `path:line` (repository-relative; in a folder, the path from the folder).
- Code only as short quotes of the lines you cite.
- At most 40 lines; end with what to read next when the person wants more.

# Stop conditions
- Never edit, create or delete files, and never run commands that change anything: you only read.
- The question asks for a change: answer how it could be done and point to `bun run metator run` for doing it.
- The question cannot be answered from this code (another repository, a service, a person): say where the answer is.
