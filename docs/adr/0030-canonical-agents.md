# ADR-0030: Agenci kanoniczni i generatory hostów (Copilot, Claude Code)

- Status: Proposed
- Data: 2026-10-26
- Doprecyzowuje: [ADR-0005](0005-canonical-agent-format.md)

## Kontekst
ADR-0005 przyjął, że agenci są pisani raz w formacie neutralnym, a pluginy hostów generują z nich pliki. Trzeba ustalić format, zasady lintu, mapowanie uprawnień na narzędzia hostów i sposób oznaczania plików wygenerowanych.

## Decyzja
- **Dokument** `Agent` (Markdown z front matter, ADR-0016) w `metator/agents/<id>.md` (`paths.agents`). Pola:
  - `id` z prefiksem `mt-`, `role` (`coordinator|worker`), `description` (kiedy używać, a kiedy nie), `tier` (`reasoning|standard|fast`);
  - `capabilities`: abstrakcyjne `read|search|edit|execute|agent|todo|web|metator:<grupa>`;
  - `delegates`, `inputs`, `output`, `userInvocable` (domyślnie tylko koordynatorzy).
- **`metator meta agents-lint`:**
  - schemat (z dokładnym polem), unikalne ID, prefiks, nazwa pliku = ID;
  - delegują tylko koordynatorzy i tylko z uprawnieniem `agent`; delegaci muszą istnieć; brak cykli delegacji (graphlib);
  - wymagane sekcje per rola (nagłówki EN/PL z szablonów);
  - budżet treści: koordynator ≤ 200 linii, worker ≤ 150.
- **Port `HostGenerator`** i dwa pluginy; każdy ma jedną tabelę nazw narzędzi i test snapshotowy:
  - `plugin-host-copilot` → `.github/agents/<id>.agent.md`: `tools`, `agents`, `model` z `hosts.models`, `user-invocable`. Copilot nie zawęża `execute` do komend, więc dozwolone grupy `metator` są wypisane w treści.
  - `plugin-host-claude` → `.claude/agents/<id>.md`: `tools` (np. `Read, Glob, Bash(<cmd> gate:*)`), `model` z konfiguracji albo alias tieru (`opus|sonnet|haiku`).
- **Konfiguracja `hosts`** (opcjonalna sekcja `MetatorConfig` v1, więc stare pliki pozostają poprawne): `targets`, `metatorCommand` (np. `bun run metator`, podstawiany w treści w miejsce `` `metator `` ), `models` per tier i host.
- **Oznaczanie:** pliki hostów zachowują format hosta, a wersję i źródło niesie znacznik `<!-- generated by metator generate from …; kind: HostFile, schemaVersion: 1 … -->`. `metator generate --check` (w `bun run canon`) wykrywa ręczne edycje i pliki osierocone; ręcznie pisane pliki hostów są pomijane.
- **Partiale** (ARCHITECTURE §11.3): `{{> nazwa}}` w treści wstawia `metator/agents/partials/<nazwa>.md` przed lintem sekcji i budżetu oraz przed generowaniem; nieznany partial to błąd. Wspólna treść (np. procedura soczewek review) istnieje raz, co wymusza też `memory dupes`.
- Dogfood: pięciu agentów MetatorAI (`mt-orchestrator`, `mt-scout`, `mt-pattern-miner`, `mt-rule-curator`, `mt-gatekeeper`) wyłącznie na istniejących komendach.

## Konsekwencje
### Pozytywne
- Zmiana nazw narzędzi u dostawcy hosta to poprawka jednej tabeli, a snapshot ją pokazuje.
- Ten sam kanon działa w Copilocie i w Claude Code, z modelami dobranymi per tier.
### Negatywne
- Skille, prompty, hooki i instrukcje ścieżkowe dla Claude (`.claude/rules`) nie są jeszcze generowane.
- Prefiks `mt-` jest stały; `naming.agentPrefix` w konfiguracji dojdzie razem z partialami i nadpisaniami (§11.3).

## Alternatywy odrzucone
| Alternatywa | Dlaczego odrzucona |
|-------------|--------------------|
| Pliki hostów pisane ręcznie | dryf między hostami i wersjami, duplikacja (ADR-0005) |
| `kind`/`schemaVersion` w front matter plików hostów | hosty walidują swój front matter; nieznane klucze dają ostrzeżenia |
| Jeden plugin dla wszystkich hostów | SRP: zmiana u jednego dostawcy nie powinna dotykać drugiego |
