# ADR-0058: Pytania do kodu: `metator ask`, agent `mt-guide`, `Conversation`

- Status: Proposed
- Data: 2026-10-28

## Kontekst
Użytkownik chce móc zadać Metatorowi zwykłe pytanie o repozytorium, np. „jak to działa” albo „gdzie to jest”. Ma to działać bez feature'a, review i całego workflowu ([design/10 §3.2](../design/10-repos-ask-tui.md)). Dotąd każdy agent należał do workflowu, a pytanie trzeba było zadać w hoście, bez narzędzi i cytatów Metatora.

## Decyzja
- **Agent `mt-guide`** (worker, kanon w `metator/agents`):
  - tylko czyta: `read`, `search`, `metator graph|symbols|similar|cards|rules|system|repos`;
  - odpowiada najpierw wprost, potem z dowodem `ścieżka:linia` przy każdej tezie, w najwyżej 40 linijkach;
  - przy prośbie o zmianę wyjaśnia, jak ją zrobić, i odsyła do `metator run`.
  
  Nie jest wywoływany przez człowieka w hoście (konwencja workerów); prowadzi do niego `metator ask`.
- **`metator ask "<pytanie>"`** uruchamia `mt-guide` przez port `AgentHost`, więc działa z Claude Code, Copilot i hostem scenariuszowym.
  - W terminalu tekst i użyte narzędzia płyną na żywo, a bez terminala wynikiem jest koperta.
  - O uprawnienia host pyta człowieka w terminalu; bez terminala są odrzucane.
- **Sprawdzanie cytatów:** każdy `ścieżka:linia` z odpowiedzi jest wyciągany (`findCitations`) i sprawdzany na dysku. Cytat nieistniejącego pliku wraca jako ostrzeżenie w kopercie: to tania osłona przed zmyśleniem.
- **`Conversation` v1** (`.metator/conversations/<id>.json`):
  - pytania i odpowiedzi z autorem, czasem, wynikiem i cytatami, do tego host i sesja hosta;
  - id to dzień i pierwsze słowa pytania, transliterowane (`ł` → `l`), z numerem przy kolizji.
- **Dopytania:**
  - `--continue` dotyczy ostatniej rozmowy, `--conversation <id>` wskazanej;
  - ten sam host wznawia własną sesję (`resume`), a inny host dostaje ostatnie trzy pytania i odpowiedzi w treści;
  - host scenariuszowy wznawia sesję `scenario-<agent>-<k>` wpisem k+1, więc dopytanie da się przetestować między procesami.
- **W folderze repozytoriów:**
  - katalogiem pracy jest folder, a pliki hosta pochodzą z pierwszego repozytorium z zainstalowanym `mt-guide`;
  - rozmowy leżą w `.metator/conversations` folderu.
- `--continue [id]` z opcjonalną wartością odrzucone: commander połykałby pytanie jako id.
- Przy okazji: `metator help` pokazuje grupę komend, która ma też własną akcję (`run`, `ask`). Wcześniej widać było tylko jej podkomendy, więc `metator run` i `metator ask` nie były w pomocy.

## Konsekwencje
### Pozytywne
- e2e na prawdziwym CLI:
  - odpowiedź z cytatami;
  - dopytanie w tej samej sesji hosta;
  - ostrzeżenie o nieistniejącym pliku;
  - `ask list`, błędy jako wartości;
  - pytanie w folderze repozytoriów.
- Rozmowa jest sesją, którą pokaże `metator ui` (G5).
### Negatywne
- Jakość odpowiedzi zależy od modelu hosta. Sprawdzamy tylko istnienie cytowanych plików, a nie to, czy linia mówi to, co twierdzi odpowiedź.

## Alternatywy odrzucone
| Alternatywa | Dlaczego odrzucona |
|-------------|--------------------|
| Własny klient API modelu w Metatorze | Metator jest niezależny od hosta; port `AgentHost` już daje Claude Code i Copilot |
| Pytanie jako krótki workflow (run) | run ma etapy, bramki i stan; pytanie potrzebuje tylko rozmowy |
| `mt-guide` z prawem zapisu | pytanie nie może zmienić kodu; zmiany idą przez `metator run` |
